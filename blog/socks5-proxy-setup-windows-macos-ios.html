How to Set Up a SOCKS5 Proxy on Windows, macOS, and iOS

Published September 18, 2026

Tether Link Utility runs a local SOCKS5 proxy on your Android phone. Any device that supports SOCKS5 proxy settings can connect to it over the phone's own Wi-Fi hotspot, no separate client app required on Windows or macOS, and a lightweight one on iOS. Here's exactly how to point each platform at it.

Before you start

Open Tether Link Utility, tap START SERVER, and note two things shown on screen: the IP address and the port. You'll enter both into whichever setup below matches your device.

Windows

Option A: Firefox (no extension needed)

  1. Go to Settings → General → Network Settings → Settings.
  2. Choose Manual proxy configuration.
  3. Enter the phone's IP under SOCKS Host, the port under Port, and select SOCKS v5.
  4. Check Proxy DNS when using SOCKS v5 to avoid DNS leaks outside the tunnel.

Option B: Chrome or Edge, via FoxyProxy

  1. Install the FoxyProxy extension from the Chrome Web Store.
  2. Add a new proxy: type SOCKS5, host = phone's IP, port = the port shown in the app.
  3. Switch FoxyProxy to that proxy from its toolbar icon.

Option C (recommended): full system coverage with sing-box

Firefox and FoxyProxy only route that one browser's traffic, DNS lookups and background app traffic can still leave over the plain hotspot connection unprotected. For every app on Windows tunneled, DNS included, use sing-box (open source, MIT-adjacent license, actively maintained) in TUN mode instead:

  1. Download the latest Windows release from github.com/SagerNet/sing-box/releases.
  2. Save the config below as config.json, replacing the IP/port with what's shown in the app.
  3. Run it from an elevated (Administrator) terminal: sing-box run --config config.json

macOS

Option A: native Network settings

  1. Open System Settings → Network.
  2. Select the Wi-Fi network you're connected to (the one the phone is broadcasting) and click Details…
  3. Go to Proxies, check SOCKS Proxy.
  4. Enter the phone's IP address and port, then click OK → Apply.

No third-party app needed, but be aware macOS's native SOCKS setting doesn't route DNS through the proxy, so DNS queries can still leak outside the tunnel even though your browsing traffic doesn't.

Option B (recommended): full system coverage with sing-box

For everything, every app, DNS included, run sing-box in TUN mode instead of the native setting above.

Easiest way: download our wrapper script, it checks for Homebrew, installs sing-box if needed, asks for your phone's IP and port, and runs everything in the background (the Terminal window minimizes and comes back only if something goes wrong).

Download tlu-mac-tunnel.zip

Unzip it, then in Terminal: chmod +x tlu-mac-tunnel.sh && ./tlu-mac-tunnel.sh

Does it actually work? Here's proof

We ran the script, downloaded a 1GB test file through the tunnel, and checked the phone's carrier account before and after. The hotspot-sharing data package showed the same amount left both times, nothing was counted against it, even though the app's own counter shows well over 1GB routed through the tunnel.

The carrier account shown is Vodafone, see the full Vodafone hotspot data breakdown.

Or set it up by hand:

  1. Install via Homebrew: brew install sing-box
  2. Save the config below as ~/config.json, replacing the IP/port with what's shown in the app.
  3. Run it (needs sudo, it creates a virtual network interface and changes routing): sudo sing-box run --config ~/config.json
  4. Turn off the native SOCKS Proxy setting from Option A if you had it on, sing-box's TUN mode replaces it entirely.

sing-box config (works for both Windows and macOS, just swap the IP/port). Leave interface_name unset so it picks an available interface automatically:

{
  "dns": {
    "servers": [
      { "type": "udp", "tag": "remote", "server": "8.8.8.8", "detour": "phone-socks5" },
      { "type": "local", "tag": "local", "detour": "direct" }
    ],
    "final": "remote"
  },
  "inbounds": [
    { "type": "tun", "tag": "tun-in", "address": ["172.19.0.1/30"], "mtu": 1500,
      "auto_route": true, "strict_route": true, "stack": "system" }
  ],
  "outbounds": [
    { "type": "socks", "tag": "phone-socks5", "server": "PHONE_IP", "server_port": PHONE_PORT, "version": "5" },
    { "type": "direct", "tag": "direct" }
  ],
  "route": {
    "rules": [ { "ip_cidr": ["PHONE_IP/32"], "outbound": "direct" } ],
    "final": "phone-socks5",
    "auto_detect_interface": true,
    "default_domain_resolver": "remote"
  }
}

Replace both PHONE_IP and PHONE_PORT with the values shown in the app (and the PHONE_IP/32 route rule too, that line keeps the tunnel from trying to route its own connection to the phone through itself). Verified working against a real carrier, QUIC/HTTP3 and DNS both tunnel correctly as of the app's latest version, which added SOCKS5 UDP ASSOCIATE support specifically for this.

iOS

Option A: Shadowrocket (paid, one-time purchase)

  1. Open Shadowrocket and tap the + button in the top right.
  2. Choose type Socks5.
  3. Enter the phone's IP as the address and the port shown in the app.
  4. Save, then tap the toggle at the top to connect.

Option B: Potatso Lite (free)

  1. Open Potatso Lite and add a new proxy profile.
  2. Select SOCKS5, enter the IP and port, and save.
  3. Enable the VPN profile when iOS prompts you, this is how Potatso routes traffic through the SOCKS5 proxy, since iOS has no native SOCKS5 setting like macOS does.

DNS tip: On every platform, make sure DNS queries are also routed through the proxy where the option exists (Firefox's "Proxy DNS when using SOCKS v5," Shadowrocket's default behavior). Otherwise DNS lookups can leak outside the tunnel even though your actual traffic doesn't, this is exactly what sing-box's TUN mode above avoids by construction, since it captures DNS along with everything else rather than relying on each app to opt in.

Android-to-Android is simpler

If both devices are Android, skip all of the above, tap Scan QR Code · Connect to Server on the client phone and point the camera at the QR code shown on the server phone. Wi-Fi and the proxy connection both complete in one tap on most devices.
